# Licensing

Republishing a dataset redistributes it, so every dataset passes a licence check before it gets a
descriptor. Each published dataset carries its LICENSE and NOTICE and keeps its canary strings. A
dataset whose licence does not allow redistribution is not republished; its metadata points at the
upstream revision instead.

## Terminal-Bench 2.0

The task directories are in [laude-institute/terminal-bench-2] at commit
`69671fbaac6d67a7ef0dfec016cc38a64ef7a77c`, licensed Apache-2.0 by their authors. The upstream
repository added its LICENSE file in commit `2ef6e27cf5888ec23adcbb72807b36b0508dfd68`
(2025-11-11), after that revision; the commit adds the file and changes nothing else.
[`datasets/terminal-bench/2.0/LICENSE`](../datasets/terminal-bench/2.0/LICENSE) is a copy of it,
and the [NOTICE](../datasets/terminal-bench/2.0/NOTICE) gives the authors and their citation.

Version 2.0 is published byte-identical, so every task keeps
`docker_image = "alexgshaw/<task>:20251031"`, a Docker Hub tag. Version 2.0.1 is the same task
directories with that one value changed in each `task.toml`: it names the task's image in node-q's
mirror, pinned by digest. Nothing else differs.

### Terminal-Bench 2.0's environment images

The images in `ghcr.io/node-q/hbench-envs/terminal-bench` are redistributed unmodified from
upstream's published images, `alexgshaw/<task>:20251031` on Docker Hub: each is copied with its
digest unchanged. Their contents, a base operating system and the packages installed on it, carry
their own licences. The Apache-2.0 licence covers the task definitions, not the images. The images
are not part of the dataset's OCI artifact.

## HumanEval+

HumanEval+ is by the EvalPlus team and is licensed Apache-2.0; its release repository adds that the
data also complies with the MIT License of OpenAI's HumanEval, which it extends. Both licences allow
redistribution and derived works with attribution.

The task directories of `humaneval-plus@1.0` are node-q's: `adapters/humaneval_plus` writes them
from `HumanEvalPlus.jsonl.gz` of the [v0.1.10 release][HumanEval+ v0.1.10], pinned by sha256, the
file EvalPlus's own evaluator downloads. Each task keeps its problem's prompt, canonical solution and
base and plus inputs unchanged; the instruction, `task.toml`, checker and environment are ours. They
are licensed Apache-2.0
([`datasets/humaneval-plus/1.0/LICENSE`](../datasets/humaneval-plus/1.0/LICENSE)), and the
[NOTICE](../datasets/humaneval-plus/1.0/NOTICE) carries EvalPlus's licence, HumanEval's MIT copyright
and permission notice, and both citations. Nothing in them comes from a third-party task repository,
so the version is clear to publish.

Its environment image, `ghcr.io/node-q/hbench-envs:humaneval-plus-1.0`, is built by this repository
from `python:3.12-slim`, whose copy is `ghcr.io/node-q/hbench-envs:base-python-3.12-slim`. It adds no
software, so it redistributes only that image's, under their own licences. The image is not part of
the dataset's OCI artifact.

## Exercism Polyglot

Exercism's problem specifications and its C++, Go, Java, JavaScript, Python and Rust tracks are
licensed under the MIT License, by Exercism. Each track's licence covers the whole repository: the
exercises' descriptions, stubs, tests, build files and example solutions. The only third-party files
in the exercises used are Catch2, under the Boost Software License 1.0, in the C++ exercises'
`test/` directories, and the Gradle wrapper, under Apache-2.0, in the Java exercises. Both licences
allow redistribution with their notices.

The task directories of `exercism-polyglot@1.0` are node-q's: `adapters/exercism_polyglot` writes them
from the seven repositories' archives at pinned commits, each pinned by sha256. Each task keeps its
exercise's files and documents unchanged, without the Gradle files, which are not needed; the
instruction's own text, `task.toml`, the verifier and the oracle script are ours and licensed
Apache-2.0 ([`datasets/exercism-polyglot/1.0/LICENSE`](../datasets/exercism-polyglot/1.0/LICENSE)).
The [NOTICE](../datasets/exercism-polyglot/1.0/NOTICE) carries Exercism's two MIT notices and Catch2's
licence, and each task names its exercise's authors and contributors. Nothing in them comes from a
third-party task repository, so the version is clear to publish.

What is left out, and why:

- `food-chain`: its song's lyrics are under copyright.
- Exercism's test runners, which are AGPL-3.0, and the solutions published on exercism.org, which
  are CC BY-NC-SA: the verifier is ours and the oracle is each track's own example solution.
- org.json 20190722, which the Java rest-api exercise's build names and which is under the JSON
  License, not an open-source licence: the Java image has the public-domain release 20260814.

Its six environment images, `ghcr.io/node-q/hbench-envs:exercism-polyglot-<language>-1.0`, are built
by this repository from official Docker Hub images (`debian:trixie-slim`, `golang:1.27-trixie`,
`eclipse-temurin:25-jdk`, `node:24-trixie-slim`, `python:3.12-slim` and `rust:1.99.1-slim-trixie`)
and add each language's compiler or test framework and the packages the tests use, each under its own
licence. The images are not part of the dataset's OCI artifact.

## Datasets from a third-party shared task repository

Today the task directories of `humanevalfix@1.0`, `swebench-verified@1.0`, `aider-polyglot@1.0`
and `livecodebench@6.0` come from a third-party shared task repository that has no LICENSE file.
The underlying data is MIT for the first three, but the task directories are adaptations (an
instruction, a Docker environment, tests and a solution per task) written by that repository's
contributors, and the data's licence does not cover them. Redistributing them needs one of:

1. **That repository's permission** to redistribute its task directories, recorded in each
   dataset's NOTICE. The datasets would then be published byte-identical, as the versions above.
2. **Our own task directories, generated from the original sources.** Those are different bytes,
   so they are published as new dataset versions, never as the versions above.

Until then, none of them has a descriptor.

### HumanEvalFix

[HumanEvalPack] (from OctoPack, by BigCode) is MIT. Its HumanEvalFix tasks can be generated from it
directly.

### SWE-bench Verified

[SWE-bench] is MIT, in its repository; its Hugging Face dataset cards state no licence. Its
prebuilt task images embed each target repository and its dependencies, GPL-2.0 code among other
licences, so they are not mirrored: a dataset version pins the upstream images by digest, with the
`pinned-upstream` environment policy.

### Aider Polyglot

The exercises come from [Exercism]'s language tracks, which are MIT. Aider's polyglot-benchmark
repository, which collects them, has no LICENSE file either, so our own task directories are built
from the Exercism tracks instead: [`exercism-polyglot@1.0`](#exercism-polyglot), a dataset of its own.

### LiveCodeBench

Its dataset's licence is "cc", with no variant or version, and its problems are scraped from
programming contest sites, whose own terms apply. It is not republished. If it is listed, only its
metadata is published, pointing at the upstream revision.
