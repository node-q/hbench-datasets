# Licensing

Republishing a dataset redistributes it, so every dataset passes a licence check before it gets a
descriptor. Each published dataset carries its LICENSE and NOTICE and keeps its canary strings. A
dataset whose licence does not allow redistribution is not republished; its metadata points at the
upstream revision instead.

## Terminal-Bench 2.0

The task directories are in [laude-institute/terminal-bench-2] at commit
`69671fbaac6d67a7ef0dfec016cc38a64ef7a77c`, licensed Apache-2.0 by their authors. The upstream
repository added its LICENSE file in commit `2ef6e27cf5888ec23adcbb72807b36b0508dfd68`
(2025-11-11), after that revision; the commit adds the file and changes nothing else.
[`datasets/terminal-bench/2.0/LICENSE`](../datasets/terminal-bench/2.0/LICENSE) is a copy of it,
and the [NOTICE](../datasets/terminal-bench/2.0/NOTICE) gives the authors and their citation.

Version 2.0 is published byte-identical, so every task keeps
`docker_image = "alexgshaw/<task>:20251031"`, a Docker Hub tag. Version 2.0.1 is the same task
directories with that one value changed in each `task.toml`: it names the task's image in node-q's
mirror, pinned by digest. Nothing else differs.

### Terminal-Bench 2.0's environment images

The images in `ghcr.io/node-q/hbench-envs/terminal-bench` are redistributed unmodified from
upstream's published images, `alexgshaw/<task>:20251031` on Docker Hub: each is copied with its
digest unchanged. Their contents, a base operating system and the packages installed on it, carry
their own licences. The Apache-2.0 licence covers the task definitions, not the images. The images
are not part of the dataset's OCI artifact.

## HumanEval+

HumanEval+ is by the EvalPlus team and is licensed Apache-2.0; its release repository adds that the
data also complies with the MIT License of OpenAI's HumanEval, which it extends. Both licences allow
redistribution and derived works with attribution.

The task directories of `humaneval-plus@1.0` are node-q's: `adapters/humaneval_plus` writes them
from `HumanEvalPlus.jsonl.gz` of the [v0.1.10 release][HumanEval+ v0.1.10], pinned by sha256, the
file EvalPlus's own evaluator downloads. Each task keeps its problem's prompt, canonical solution and
base and plus inputs unchanged; the instruction, `task.toml`, checker and environment are ours. They
are licensed Apache-2.0
([`datasets/humaneval-plus/1.0/LICENSE`](../datasets/humaneval-plus/1.0/LICENSE)), and the
[NOTICE](../datasets/humaneval-plus/1.0/NOTICE) carries EvalPlus's licence, HumanEval's MIT copyright
and permission notice, and both citations. Nothing in them comes from a third-party task repository,
so the version is clear to publish.

Its environment image, `ghcr.io/node-q/hbench-envs:humaneval-plus-1.0`, is built by this repository
from `python:3.12-slim`, whose copy is `ghcr.io/node-q/hbench-envs:base-python-3.12-slim`. It adds no
software, so it redistributes only that image's, under their own licences. The image is not part of
the dataset's OCI artifact. `humanevalfix@1.0`, `mbpp-plus@1.0` and `cruxeval-input@1.0` run in the
same image.

## HumanEvalFix, MBPP+ and CRUXEval-I

Their task directories are node-q's too, each written by its adapter from one upstream file pinned
by sha256, licensed Apache-2.0, with a NOTICE that carries every upstream licence notice, copyright
line and citation. Nothing in them comes from a third-party task repository, so they are clear to
publish.

- **HumanEvalFix** is the bug-fixing part of [HumanEvalPack], by BigCode, MIT (copyright 2023
  Muennighoff), which extends HumanEval, MIT. `adapters/humanevalfix` reads the Python
  `humanevalpack.jsonl` at revision `7980d99405b56c9745d51040cabbd9e86a056397`. A third-party shared
  task repository, below, also has a `humanevalfix@1.0`; it was never configured here, and this
  repository's `humanevalfix@1.0` is node-q's own generation, different bytes.
- **MBPP+** is by the EvalPlus team, Apache-2.0, and is derived from Google's [MBPP], whose data is
  CC BY 4.0. That licence allows adaptations and redistribution with attribution, a link to the
  licence and a note of the changes, which the NOTICE gives. `adapters/mbpp_plus` reads
  `MbppPlus.jsonl.gz` of the [MBPP+ v0.2.0 release][MBPP+].
- **CRUXEval** is by Meta, MIT (copyright 2023 Meta). Its functions were generated with Code Llama
  34B, whose licensor, Meta, is the dataset's copyright holder and released the dataset under MIT.
  `adapters/cruxeval_input` reads `test.jsonl` at revision
  `b96af0450242eb4da433032b90998f25588a5d0f` and writes only the input-prediction task.

## BigCodeBench

BigCodeBench, by the BigCode project, is licensed Apache-2.0: its dataset card says so, and its
repository's LICENSE file is that licence, with no NOTICE file. Its paper's datasheet (arXiv
2406.15877, C.3) answers "No" to "Will the dataset be distributed to third parties outside of the
entity (…) on behalf of which the dataset was created?", adding "Our dataset will be managed and
maintained by the BigCode community", and then that it is "released to the public, and hosted on
Hugging Face" and "distributed under the Apache-2.0 license". The "No" describes who maintains the
dataset; it is not a term of its licence.

The task directories of `bigcodebench@1.0` are node-q's: `adapters/bigcodebench` writes them from
the [v0.1.4 split][BigCodeBench v0.1.4], pinned by sha256, the split BigCodeBench's own evaluator
reads. Each task keeps its problem's complete prompt, code prompt, canonical solution and unit tests
unchanged; the instruction, `task.toml`, checker and environment are ours. They are licensed
Apache-2.0 ([`datasets/bigcodebench/1.0/LICENSE`](../datasets/bigcodebench/1.0/LICENSE)), and the
[NOTICE](../datasets/bigcodebench/1.0/NOTICE) carries BigCodeBench's licence and citation, and the
MIT notice of OpenAI's HumanEval, which BigCodeBench's execution harness carries and the checker
follows.

BigCodeBench-Hard's dataset card states no licence, so nothing of it is published: its tasks are
made from the full split's rows, which its split repeats unchanged, and only its task IDs are used,
to tag those tasks `hard`.

Its environment image, `ghcr.io/node-q/hbench-envs:bigcodebench-1.0`, is built by this repository
from `python:3.10-slim-bookworm`, whose copy is `ghcr.io/node-q/hbench-envs:base-python-3.10-slim-bookworm`.
It adds BigCodeBench's evaluation requirements, at the versions in
[`images/bigcodebench/requirements.txt`](../images/bigcodebench/requirements.txt), and five NLTK data
packages, all under their own licences. The image is not part of the dataset's OCI artifact.

## Datasets from a third-party shared task repository

Today the task directories of `swebench-verified@1.0`, `aider-polyglot@1.0` and
`livecodebench@6.0` come from a third-party shared task repository that has no LICENSE file. The
underlying data is MIT for the first two, but the task directories are adaptations (an instruction,
a Docker environment, tests and a solution per task) written by that repository's contributors, and
the data's licence does not cover them. Redistributing them needs one of:

1. **That repository's permission** to redistribute its task directories, recorded in each
   dataset's NOTICE. The datasets would then be published byte-identical, as the versions above.
2. **Our own task directories, generated from the original sources.** Those are different bytes,
   so they are published as new dataset versions, never as the versions above.

Until then, none of them has a descriptor.

### SWE-bench Verified

[SWE-bench] is MIT, in its repository; its Hugging Face dataset cards state no licence. Its
prebuilt task images embed each target repository and its dependencies, GPL-2.0 code among other
licences, so they are not mirrored: a dataset version pins the upstream images by digest, with the
`pinned-upstream` environment policy.

### Aider Polyglot

The exercises come from [Exercism]'s language tracks, which are MIT. Aider's polyglot-benchmark
repository, which collects them, has no LICENSE file either, so our own task directories would be
built from the Exercism tracks.

### LiveCodeBench

Its dataset's licence is "cc", with no variant or version, and its problems are scraped from
programming contest sites, whose own terms apply. It is not republished. If it is listed, only its
metadata is published, pointing at the upstream revision.
